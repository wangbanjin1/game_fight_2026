# 《未来战争》选手程序 设计文档

| 版本 | 描述     | 时间       |
| ---- | -------- | ---------- |
| v0.1 | 初步方案 | 2026-09-10 |

# 一、概述

本程序是云核心网编程大赛《未来战争》的参赛 AI，以 HTTP Server 方式常驻运行，
监听判题系统下发的端口，每回合接收地图状态（Request JSON），返回三名角色
（开拓者 ×1、工人 ×2）及武器工事的调度指令（Response JSON）。

- 语言：Python 3（仅标准库，无第三方依赖）
- 启动方式：`bash run.sh <port>`（本地 Windows 调试用 `run.bat <port>`）

# 二、总体架构

```
判题系统 ──POST(状态)──> main.py (HTTP 服务层)
                            │
                            ▼
                      models.parse()   请求 JSON → GameState 数据模型
                            │
                            ▼
                      Strategy.decide() 决策层
                       ├─ 白天: 采集 / 建造 / 贩卖 / 任务 / 回撤
                       └─ 黑夜: 武器绑定 / 目标选择 / 攻击
                            │
                            ▼
                      Response JSON (roleCommandMap / prompt / executeCmd)
```

## 2.1 模块划分

| 模块                | 职责                                                         |
| ------------------- | ------------------------------------------------------------ |
| `src/main.py`       | HTTP 服务、请求收发、JSON 宽松解析、全局异常兜底             |
| `src/models.py`     | 数据模型（GameState/Role/Zone/PlayerTask/Pos）与请求解析     |
| `src/strategy.py`   | 决策核心：昼夜状态机、经济循环、武器操控、跨回合记忆         |
| `src/pathfind.py`   | 贪心单步移动（8 方向，避开已知障碍）                         |
| `test/smoke_test.py`| 冒烟测试：起服务并 POST `docs/request.txt` 校验响应结构      |

## 2.2 关键设计约束

- **每回合每角色至多 1 条指令**；武器攻击指令挂在武器 ID 上，由 `controllerId`
  指定操控角色。
- **5 秒响应时限**：所有决策均为 O(单位数 × 格子数) 的轻量计算，远低于时限。
- **异常零容忍**：异常响应累计 5 次即被取消调度。`main.py` 与
  `Strategy.decide()` 双层 try/except 兜底，任何异常都退化为合法空响应；
  JSON 解析对样例中可能出现的尾逗号做宽松处理。
- **跨回合记忆**：进程常驻，利用 `lastRoundRoleActionResults` 反馈修正行为
  （见 4.3 建造黑名单）。

# 三、时间与阶段判定

一天 130 回合（白天 70 + 黑夜 60）。由 `roundNo` 推导：

- `day_index = (roundNo - 1) // 130 + 1`
- `round_in_day = (roundNo - 1) % 130`
- `is_day = round_in_day < 70`

白天末尾（`round_in_day >= 55`）所有角色停止生产活动，回撤至基地/武器附近，
保证黑夜第 1 回合即可操控武器开火。

# 四、策略设计

## 4.1 白天 —— 经济循环（工人）

工人按优先级执行：

1. **建造武器**（仅 1 号工人负责，避免两名工人争抢同一建造点）：
   金币 ≥ 25 且武器数 < 3 时，在基地周围 2~4 格环带选址，依次建造
   加特林 → 电磁狙击炮 → 火箭发射台。建造点距工人超过 1 格时先走位。
2. **贩卖矿石**：背包矿石 ≥ 15，或（尚未造满武器且金币 < 25 且背包有矿）时，
   前往小贩；相邻后按"单价 × 数量"收益最高的矿种批量卖出。
3. **采集**：前往最近的矿区（石/铁/铜），相邻后执行 `collect`。

## 4.2 白天 —— 任务（开拓者）

- 无进行中任务：前往最近的 `isValid` 任务点，相邻后 `acceptTask`。
- 任务进行中（`phaseTask` 非空）：先通过 Response 的 `prompt` 字段把题目交给
  LLM；下一回合从 Request 的 `llmResp` 拿到回答后执行 `submitAnswer`。
  用 `waiting_llm` 标志位维护该两阶段状态，任务期间不计 LLM 日限额。

## 4.3 建造选址与失败黑名单

接口的 `zones` 不含可建造区域信息，因此采用**试探式建造**：

- 候选点为基地（2×2，pos 为左上角）周围切比雪夫距离 2~4 的环带空格，
  按离工人的距离排序逐一尝试；
- 每回合发出的 `build` 记入 `pending_builds`；下回合若
  `lastRoundRoleActionResults[roleId] == false`，将该坐标加入
  `failed_builds` 黑名单，永不再试。

## 4.4 黑夜 —— 武器操控与目标选择

- **绑定**：三座武器按 ID 顺序各绑定一名最近的空闲角色（一角色只控一武器）；
  未就位（距武器 > 1 格）则走位，就位后输出 `attack`。
- **目标选择**（仅打切比雪夫距离 ≤ 攻击距离的机器人，跳过被眩晕目标）：
  - 加特林：按距离/血量排序取锚点，后续目标须与已选目标两两方向夹角
    ≤ 90°（方向向量点积 ≥ 0 判定），目标数不超过武器等级；
  - 电磁狙击炮：单目标，优先低血量（确保击杀拿积分），同血量取最近；
  - 火箭发射台：冷却为 0 时，选"周围 8 格机器人最多"的密集落点，
    目标数不超过武器等级。
- **未绑定角色**：撤到基地附近，避免无谓伤亡（阵亡要等次日白天复活）。

## 4.5 移动与避障

贪心单步：从 8 个方向中选取"不越界、不在阻挡集合内、切比雪夫距离不增大"
中最优的一格；平局时按曼哈顿距离 tie-break。阻挡集合每回合重建，包含：
中立元素（矿区/小贩/商店/任务点）、双方可见单位、机器人，
以及基地按 2×2 展开的 4 格。目标格本身被占（矿、小贩、武器）时，
改为向其最近的相邻空格移动。

# 五、数据结构

核心模型见 `src/models.py`：

- `Pos(x, y)`：坐标，`cheb()` 计算切比雪夫距离；
- `Role`：单位通用属性（id/pos/roleType/health/level/cooldown/backpack 等），
  角色、建筑、机器人复用；
- `GameState`：一回合全部战场信息 + 时间属性（`day_index`/`round_in_day`/`is_day`）
  + 便捷查询（`our_units()`/`our_weapons()`/`our_station()`/`find_zone()`）。

`Strategy` 持有的跨回合状态：

| 字段              | 用途                                       |
| ----------------- | ------------------------------------------ |
| `failed_builds`   | 建造失败坐标黑名单                         |
| `pending_builds`  | 上回合 build 指令，用于对照执行结果        |
| `waiting_llm`     | prompt 已发出、等待 llmResp 回填           |

# 六、已知限制与后续迭代方向

1. **宝藏（长上下文任务）**：尚未实现民间传闻解析、任务用品购买与
   `summonTreasure`。计划：从 `folkLegends` 抽取物品/地点/时间线索，
   配合商店任务用品清单做匹配。
2. **官方消息套利**：未利用价格波动（如铁矿停工前囤货、涨价后抛售）。
3. **寻路**：贪心单步可能在小 U 形障碍前抖动，后续换 BFS（地图仅 41×32），
   并利用移动碰撞规则做己方角色目标点去冲突。
4. **围墙与升级**：暂未建造围墙、未购买升级券。计划：武器满 3 座后，
   金币盈余优先升级武器（升满回满血相当于一次大修），石头盈余补围墙。
5. **召唤令/炸弹等消耗品**：暂未使用，可作为压制对方的进攻手段。
6. **自进化任务 SOP**：当前每次任务都从零问 LLM，后续把同类任务的解题
   过程沉淀为可复用 SOP，通过 `executeCmd` 沙盒命令加速。
7. **加特林目标数**：当前传入"实际可用目标数"（≤ 等级），任务书要求
   目标数与等级一致，需实测确认少传是否判非法，必要时重复落点补齐。

# 七、测试

```bash
# 冒烟测试：启动服务 → POST docs/request.txt → 校验响应结构
python test/smoke_test.py
```

已验证场景：
- 黑夜（roundNo=85）：三名角色正确绑定最近武器并向其走位；
- 白天（roundNo=5）：开拓者走向任务点、1 号工人建造加特林、2 号工人
  走向最近矿区；
- 宽松 JSON 解析可处理样例报文中的尾逗号。
